1. 총평

화면 구성과 번호(❶❷❸) 체계, 업무·화면·기능·조회 조건으로 나눈 설명 틀은 일관되게 잡혀 있습니다. 다만 개발자가 이 문서만 보고 구현하기에는 아래 세 가지 문제가 큽니다.

  • 다른 프로젝트(매입 견적 산출) 문구가 그대로 남아 있습니다. 화면 4개(슬라이드 7–8, 12–14, 15–17, 18–19)에 영업이익·재고비용·품목·상태·등급·BASE_MONTH·MSE 같은 이 시스템과 무관한 내용이 들어 있어, 개발자가 그대로 구현하면 잘못된 기능이 만들어집니다.
  • 불량 클래스 정의가 화면마다 다릅니다. 설명에는 stick_offset, thread_defection 등으로 정의했지만 화면 예시에는 broken_thread, bond_leak, broken_bar가 나오고, 다른 화면은 한글명(엮음실 불량, 풀림)을 씁니다. 코드·한글명·클래스 번호를 연결하는 기준표가 없습니다.
  • YOLO 객체 검출에 맞지 않는 지표와 개념이 쓰였습니다. 정확도·MSE·0~1 정규화는 회귀 모델 기준이고, 모든 불량을 class : 1로 표기한 것은 YOLO의 클래스 번호 체계와 충돌합니다.

2-2. 불량 클래스 기준표 필요

지금은 화면마다 다른 이름이 쓰여 개발자가 DB 코드값과 화면 표시명을 정할 수 없습니다. 문서 앞쪽에 아래와 같은 기준표를 한 장 두고, 모든 화면이 이를 참조하게 하세요. (예시이며 최종 코드는 확정 필요)

YOLO class id코드한글명정의현재 문서에 쓰인 다른 이름
0stick_offset살 조립 이탈살이 튀어나와 있음-
1stick_broken살 끊김 불량살이 중간에 끊겨 있음broken_bar
2thread_defect엮음실 불량엮음 실이 튀어나와 있음thread_defection, broken_thread

YOLO 검출에서 정상 이미지는 클래스가 아니라 '박스 없음(빈 라벨)'입니다. 따라서 정상/불량 여부는 클래스 번호가 아니라 "검출된 박스가 있는가"로 정해진다는 점도 함께 적어 주세요.

2-3. 공통 컴포넌트 규칙이 정의되지 않음

모든 화면에 반복되는 요소지만 동작이 어디에도 정의되어 있지 않습니다. 공통 규칙 페이지를 하나 추가하면 화면별 설명이 짧아지고 구현도 일관됩니다.

  • 조회 조건 입력: 날짜는 달력 선택인지 직접 입력인지, 라인 번호·불량 여부·불량 유형은 드롭다운인지와 선택 가능한 값 목록. 시작일 > 종료일, 최대 조회 기간 같은 입력 검증 규칙.
  • 아이콘: 조회 조건 왼쪽의 필터 아이콘, 오른쪽 돋보기 아이콘, 목록 제목 오른쪽 다운로드 아이콘의 동작. 다운로드는 파일 형식(xlsx/csv/zip)과 범위(현재 페이지/전체 조회 결과)까지.
  • 페이징: 화면마다 21·8·12·7·12건으로 다르고, 예시는 항상 5페이지가 보이지만 60건 ÷ 21건이면 3페이지입니다. 페이지 번호 표시 개수, 처음/이전 버튼 비활성 조건, 조건 변경 시 1페이지 복귀 여부를 정의해야 합니다.
  • 정렬 동점 처리: 같은 촬영 시각이 여러 라인에서 생길 때의 2차 정렬 기준.
  • 상태 화면: 조회 결과 없음, 로딩 중, 오류(이미지 로드 실패 포함) 때 표시할 내용.
  • 권한: 메뉴(데이터처리 / AI 모델링 / AI 서비스)별 접근 권한이 사용자 역할에 따라 다른지.

2-4. 화면 간 데이터 흐름과 연결 정보 부재

문서는 원본 이미지 → 전처리 데이터 → 학습 → 검증 → 합불 판정 → 내역·대시보드 순서로 구성되어 있지만, 화면 사이를 잇는 정보가 없습니다.

  • 원본 이미지(슬라이드 2)와 전처리 이미지(슬라이드 4)가 같은 건임을 잇는 이미지 ID가 화면에 없습니다.
  • 어떤 전처리 데이터로 어떤 모델을 학습했는지(슬라이드 7), 합불 판정(슬라이드 15)에 어느 모델이 쓰였는지 알 수 없습니다. 운영 모델을 지정하는 화면이나 표시가 필요합니다.
  • 대시보드(슬라이드 12–13)의 생산량·불량수가 AI 판정 결과(슬라이드 18)에서 집계되는지, 별도 생산 실적에서 오는지 명시가 필요합니다.

2-5. 예시 데이터 불일치

  • 슬라이드 2, 15의 조회 조건은 2026-10-17 ~ 10-23 또는 2026-10-23인데, 목록 예시 데이터는 2026-09-02입니다. 개발자가 조회 조건의 기준 컬럼을 오해할 수 있습니다.
  • 목록 건수 표시(1 - 21 / 60)와 페이지 번호(1~5)가 맞지 않습니다.

2-6. 문서 구성

  • 화면 ID가 TD3-001, 002, 005, 006, 009, 010, 011로 건너뜁니다. 빠진 번호(003, 004, 007, 008)가 의도된 것인지 표기해 주세요.
  • 표지 3장의 문서코드가 모두 SF-TD1입니다. 한 문서의 장 구분이면 표지 대신 간지로, 별도 문서면 코드를 다르게 하는 것이 좋습니다. AI 모델링 표지는 작성자가 비어 있습니다.
  • 개정 이력, 목차, 메뉴 구조도가 없습니다.
  • 불량 여부를 테두리 색(빨강/초록)만으로 구분합니다. 색각 이상 사용자를 위해 아이콘이나 텍스트 배지를 함께 표시하는 것을 권장합니다.

3. 페이지별 피드백

표지 (슬라이드 1, 6, 11)

  • 낮음 세 표지의 문서코드가 모두 SF-TD1이고, 화면 ID는 TD3, 프로그램 ID는 TD4 접두어를 써서 체계가 연결되지 않습니다.
  • 낮음 슬라이드 6(AI 모델링 표지)의 작성자가 비어 있습니다.

TD3-001 품질검사 데이터 조회 (슬라이드 2–3)

설명이 화면 구성을 충분히 설명하는가

  • 중간 조회 조건 입력 방식(달력, 드롭다운)과 라인 번호 선택값 목록이 없습니다.
  • 중간 필터 아이콘, 조회 아이콘, ❷ 오른쪽 다운로드 아이콘의 동작이 없습니다.
  • 중간 썸네일을 클릭했을 때의 동작(원본 확대, 상세 화면 이동 등)이 정의되지 않았습니다.

개발자가 의도를 이해할 수 있는가

  • 낮음 "최근 촬영 시각이 상단"은 표 기준 표현입니다. 썸네일 그리드는 '왼쪽→오른쪽, 위→아래 순으로 최신순'처럼 방향까지 적어 주세요.

기술적인 문제

  • 중간 한 페이지에 원본 이미지 21장을 띄우면 느려집니다. 목록에는 썸네일을 쓰고 원본은 클릭 시 불러온다는 규칙이 필요합니다.
  • 중간 21건씩이면 60건은 3페이지인데 페이징은 5페이지까지 보입니다.

다른 페이지와의 일관성

  • 중간 조회일자는 2026-10-17 ~ 10-23인데 예시 이미지 촬영일은 2026-09-02입니다.
  • 낮음 썸네일의 Lane1이 슬라이드 15·18의 라인 번호 1과 표기가 다르고, 일시 형식 2026-09-02-11:03:55도 슬라이드 7·9와 다릅니다.

기타

  • 낮음 조회 조건의 마지막 줄(라인 번호와 불량 여부의 기본값…)만 회색 글씨입니다. 작성 중 표시라면 확정 후 검정으로 바꿔 주세요.
  • 낮음 "불량 여부 선택을 통해 정상, 불량, 전체 조회를 변경한다"는 ❶ 설명과 겹칩니다.

TD3-002 품질검사 전처리 데이터 조회 (슬라이드 4–5)

설명이 화면 구성을 충분히 설명하는가

  • 높음 화면 설명 ❶은 "분류 유형, 불량 유형"이지만 화면과 기능 설명은 "라인 번호, 불량 여부, 불량 유형"입니다.
  • 높음 ❷ 설명은 "라인 번호, 불량 여부, 불량 유형을 표시"인데, 화면에는 라인 번호와 촬영 일시가 없고 class : 번호와 클래스명만 있습니다.
  • 높음 +++++ [실제 데이터 전처리 관련 주요 내용 추가] 작성 중 표시가 남아 있습니다. 전처리 내용(김발장 영역 1:1 자르기, 크기 조정, 라벨 파일 형식)이 이 화면의 핵심인데 비어 있습니다.
  • 중간 이미지 위 초록색 검출 박스(바운딩 박스)에 대한 설명이 없습니다. 박스 색, 라벨 표시 여부, 한 이미지에 박스가 여러 개일 때의 표시 방법이 필요합니다.

개발자가 의도를 이해할 수 있는가

  • 중간 조회 전용 화면인지, 라벨을 확인·수정하는 화면인지 알 수 없습니다. 라벨을 누가 어디서 만드는지도 적어 주세요.

기술적인 문제

  • 높음 모든 불량을 class : 1, 정상을 class : 0으로 표기했습니다. YOLO에서 class 번호는 불량 유형마다 다르고, 정상 이미지는 박스가 없는 빈 라벨입니다. 이대로면 개발자가 class 0을 '정상' 클래스로 학습시키는 잘못된 구조를 만들 수 있습니다.
  • 높음 화면 예시 클래스명(broken_thread, bond_leak, broken_bar)이 설명에 정의된 5종 어디에도 없습니다.
  • 중간 thread_defection은 '이탈'이라는 뜻이라 thread_defect가 적절하고, 풀림의 broken은 살 끊김(stick_broken)과 헷갈립니다.

다른 페이지와의 일관성

  • 낮음 상단 메뉴 경로에 '데이터처리 >'가 빠졌습니다. 다른 화면은 모두 '대메뉴 > 화면명' 형식입니다.
  • 낮음 슬라이드 2와 달리 목록 영역에 테두리가 없습니다.

기타

  • 낮음 오타: "불량 여부은" → "불량 여부는", "다음과 같다" 마침표 누락.
  • 낮음 2행 첫 번째 썸네일의 라벨이 이미지와 겹쳐 있습니다.
수정 제안: 목록 항목을 "썸네일(검출 박스 포함), 촬영 일시, 라인 번호, 불량 여부, 불량 유형(한글명)"으로 확정하고, class 표기는 2-2 기준표의 id와 코드로 바꾸세요.

TD3-005 품질검사 AI 모델링 (슬라이드 7–8)

설명이 화면 구성을 충분히 설명하는가

  • 높음 슬라이드 5와 같은 +++++ 작성 중 표시와 클래스 정의가 그대로 복사되어 있습니다. 클래스 정의는 기준표 참조로 바꾸세요.
  • 중간 ❷ 전처리 목록은 한 줄 7칸 그리드인데 "페이지당 8건"이라 두 번째 줄에 1건만 들어갑니다. 화면 예시도 두 번째 줄이 잘려 있어 배치를 판단할 수 없습니다.
  • 중간 비고 컬럼에 무엇을 표시하는지 없습니다.

개발자가 의도를 이해할 수 있는가

  • 높음 화면명은 "AI 모델링"인데 학습 실행 기능(데이터셋 선택, 파라미터, 학습 시작, 진행 상태)이 없습니다. 학습이 배치로 자동 실행된다면(예시상 매일 09:00) 그 사실과 주기를 적어 주세요.
  • 중간 ❷ 데이터와 ❸ 모델 사이에 어떤 데이터로 어떤 모델을 학습했는지 연결 정보가 없습니다.
  • 중간 ❶ 날짜 조건이 ❸에만 적용된다면, 화면에서도 ❸ 영역에 붙여 사용자가 혼동하지 않게 하세요.

기술적인 문제

  • 높음 "❷ 전처리 데이터는 최신 완료 집계월(BASE_MONTH) 한 달을 조회"는 월 집계 데이터 개념으로, 이미지 데이터에는 해당하지 않습니다. '학습에 사용된 데이터셋 버전' 같은 기준으로 다시 정의해야 합니다.
  • 낮음 오타: DATIME → DATETIME, "AI 학습 정도" → "AI 학습 정보". 조건 라벨 '학습일자'와 설명 '학습일시'도 맞춰 주세요.

다른 페이지와의 일관성

  • 중간 ❸ 학습 정보 조회는 슬라이드 9의 목록과 데이터가 같은데 페이지당 건수(8 vs 12)와 컬럼이 다릅니다. 중복이면 TD3-006(슬라이드 9)으로 이동하는 링크로 바꾸는 것도 방법입니다.
  • 낮음 원본 pptx의 도형 이름에 '매입 견적 산출 전처리 데이터'가 남아 있습니다. 개발자가 파일을 열어 보면 혼란스러울 수 있습니다.

TD3-006 품질 검사 AI 모델 검증 (슬라이드 9–10)

설명이 화면 구성을 충분히 설명하는가

  • 중간 표시 기준(소수 4자리, NULL 표기)은 잘 정의되어 있습니다. 다만 비고에 "손실함수명, 스케일링, 검증기간, 저장 에포크"를 기록한다면서 예시가 비어 있어 형식을 알 수 없습니다. 예시 한 줄을 채워 주세요.
  • 낮음 "화면의 수량과 손실 값은 예시"라고 했지만 화면에 수량 항목이 없습니다.

개발자가 의도를 이해할 수 있는가

  • 높음 화면명은 "검증"이지만 조회만 있습니다. 모델 비교, 운영 적용 모델 지정(합불 판정에 쓸 모델 선택) 기능이 필요한지 결정하고 적어 주세요. 운영 모델 표시 컬럼이 없으면 합불 판정(슬라이드 15)이 어떤 모델을 쓰는지 알 수 없습니다.
  • 중간 "기존 정확도(ACCURACY)의 퍼센트 표시를 유지한다"의 '기존'이 가리키는 대상이 이 문서에 없습니다.

기술적인 문제

  • 높음 YOLO 객체 검출 모델에 정확도(Accuracy)와 "목표값을 0~1 정규화한 MSE"는 맞지 않습니다. 이는 회귀(가격 예측) 모델의 지표입니다. 검출 모델은 보통 Precision, Recall, mAP@0.5, mAP@0.5:0.95를 쓰고, 손실은 box_loss, cls_loss, dfl_loss로 나뉩니다. 불량 유형별 AP도 함께 보여 주는 것을 권장합니다.
  • 중간 "손실 값의 조건은 비고에서 확인한다"가 모호합니다. 어떤 조건인지 구체적으로 적어 주세요.

다른 페이지와의 일관성

  • 낮음 화면명 '품질 검사'(띄어쓰기)가 다른 화면의 '품질검사'와 다릅니다.
  • 낮음 슬라이드 7과 같은 학습 목록인데 페이지당 건수가 다릅니다(12 vs 8).

TD3-009 대시보드 (슬라이드 12–14)

설명이 화면 구성을 충분히 설명하는가

  • 높음 ❷ 그래프의 가로축은 Jul-25 ~ Jan-26(7개월)인데 표시 기간은 2025-10 ~ 2026-09(12개월)입니다. 마지막 Jan-26은 '평균'이 날짜로 잘못 변환된 것으로 보입니다.
  • 중간 불량률 계산식과 단위가 없습니다. 0.34는 %(932 ÷ 276,200 × 100 ≈ 0.34%)로 보이므로 축과 레이블에 % 표기가 필요합니다.
  • 중간 시간당 생산량의 계산식(월 생산량 ÷ 가동 시간)과 데이터 출처가 없습니다.

개발자가 의도를 이해할 수 있는가

  • 중간 기능 설명은 두 그래프를 15초마다 번갈아 보여준다고 하지만, 화면은 ❶❷ / ❸❹로 나뉘어 따로 있는 것처럼 보입니다. 한 영역에서 번갈아 표시하는지 명시하고, 현재 순서 표시, 일시 정지, 수동 전환 여부도 적어 주세요.
  • 낮음 ❸ 표시 기간은 ❶과 같은 설명이 반복됩니다. 같은 컴포넌트라면 하나로 합치세요.

기술적인 문제

  • 높음 총생산량 위에 불량수량을 쌓으면, 총생산량에 불량이 포함된 경우 막대 높이가 이중 계산됩니다. '양품 + 불량'을 쌓거나 막대를 겹쳐 그리는 방식 중 하나로 정해 주세요. 설명의 "겹친 막대"가 누적인지 겹침인지도 모호합니다.
  • 중간 왼쪽 축이 258,480부터 시작하고 눈금이 5,000 간격의 어색한 값입니다. 막대그래프 축을 0이 아닌 값에서 시작하면 차이가 과장되니, 축 최소값과 눈금 규칙, 천 단위 쉼표 표기를 정해 주세요.
  • 낮음 시간당 생산량 그래프에서 '1,385' 레이블이 선과 겹칩니다. 단위도 (개)인데 다른 자료는 '매'를 씁니다.

다른 페이지와의 일관성

  • 높음 기능 설명의 "영업이익을 그래프와 재고비용 그래프"는 다른 프로젝트 문구입니다. "완제품 불량률 그래프와 시간당 생산량 그래프"로 고쳐야 합니다.
  • 낮음 목록 제목 '완제품불량률' · 그래프 제목 '월별 불량율' · 설명 '불량율'이 섞여 있습니다.

TD3-010 AI 기반 품질검사 합불 판정 (슬라이드 15–17)

다른 페이지와의 일관성
